## 新增计算侧结果

`kernel_shapes.py` 将 VLM q/k/v/out/gate/up/down、逐头 QK/AV 以及 DiT
线性层/注意力拆为具名 GEMM，核对其 FLOP 总和与既有工作负载一致。
这验证的是内部一致性，**不是部署 checkpoint 形状真实性**。
SigLIP 仅有聚合参数量，不能唯一反推出真实算子；非预计算 adaRMS 也明确拒绝。

`NeuSimTiming` 使用隔离、逐文件哈希校验的 NeuSim 源码快照。严格模式拒绝
未解析 SigLIP；仅显式允许回退时运行混合探索。当前仅支持未行切片的方阵、
bf16 权重和整数核心分组，关闭小矩阵自动 VU 映射，避免重复计入 DRAM。
向量/归一化、真实 SRAM/NoC 成本未覆盖，逐头 GEMM 顺序累加也不是经验证的硬件调度。

下面是 30/120 请求得到相同均值的混合结果，单位 ms：

| 核数 | Serial L / S | Pipeline k=2 L / S |
| ---: | ---: | ---: |
| 1 | 203.608 / 203.608 | 不适用 |
| 2 | 124.917 / 124.917 | 363.014 / 150.746 |
| 4 | 85.994 / 85.994 | 255.393 / 89.624 |
| 8 | 83.037 / 83.037 | 247.006 / 85.430 |

共评估 69 个唯一 GEMM 形状、14 次混合请求仿真。21,786 是包含 balance 策略
进度估算在内的 SigLIP 回退调用次数，不是请求数或唯一 kernel 数。
这些配置禁用了行切片，不能与原始 sliced v2 扫描直接混为最终架构排名。

权威结果：`results/compute_sa_checked/compute_report.json`。
`results/compute/` 是加入切片限制前的历史探索，`results/compute_sa/` 是最终来源
校验前的历史结果，均不作为最终验收依据。

## 收敛与任务覆盖

全部 198 组配对中，30/120 请求的最大 L 相对差为 `1.1471e-10%`，
S 为 `1.1708e-10%`。每次分别预热 6/24 请求。这仅说明确定性模型、当前候选和
33 个采样点上的数值稳定，不证明连续不确定区间或真实随机执行已经收敛。
权威结果：`results/convergence_interval/convergence_report.json`。

任务表覆盖 L=100–800 ms、S=50–800 ms，共 33 点。只在测量凸包内部插值，
使用原始 robust CSV 的相关 L/S 对，不把包围盒角点当作真实样本。

## 真正剩余的阻塞

1. **状态模型泛化失败。** 更小流量和连续突发仍超过 10% 门槛。后续模型必须以
   这些失败样本作为已知开发数据，另冻结全新验证集；不能复用它们声称独立通过。
2. **缺部署形状与映射。** 需要 checkpoint 版本/哈希、完整 SigLIP 与向量算子形状、
   dtype、批处理和时间步语义，以及行切片和 kernel 调度的已验证 NeuSim 映射。
3. **缺独立执行捕获。** 需要与实际模型关联的 kernel 时间戳、地址/布局、读写、
   burst、优先级和并发信息，才能做独立 VLA 端到端回放。
4. **缺任务实验出处和分母。** 需要 checkpoint/环境版本、延迟注入定义、逐速度
   试验数与结果，并补测低于 100 ms 的候选区域。现有表不能支撑最终任务排名。
5. **缺成本标定。** 需要指定工艺、频率、SRAM/阵列面积和动态/静态能耗来源。
   现有占位系数不能支撑面积/能耗 Pareto 或芯片推荐。

这些缺口无法通过继续运行现有脚本或把未知项填成常数解决。本轮没有伪造缺失输入，
没有把失败组移出验收，也没有更换 v2 校准来掩盖模型误差。工程和可执行实验已经
推进到上述边界；最终硬件、成功率和能耗结论仍需这些外部证据及新的独立实验。
